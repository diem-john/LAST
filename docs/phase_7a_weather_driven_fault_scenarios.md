# Phase 7A — Weather-Driven Probabilistic Branch Fault Scenarios

## Purpose

Generate reproducible branch-outage contingencies from the existing Phase 6B
weather-to-synthetic-IEEE-33 asset feature table. This phase reuses the existing
geographic sample mapping; it does not create a second bus/branch coordinate map.

## Inputs

1. \`reports/environmental/ieee33_weather_asset_features.csv\`, generated by
   \`scripts/map_weather_features_to_ieee33.py\`.
2. A versioned fragility configuration JSON. The repository's
   \`config/weather_fragility_demo.json\` is explicitly **uncalibrated and for
   software integration only**.
3. \`data/electrical/ieee33bw_reference.json\`.

## Current hazard adapters

- Direct wind speed in \`m s-1\` or \`m/s\`.
- ERA5 \`u10\` and \`v10\` components in \`m s-1\`, combined into vector magnitude
  when both components exist for the same asset and timestamp.
- An explicit \`flood_depth\` variable in metres can be consumed if a separate,
  valid flood-depth sampling adapter supplies it. Global Flood Database event
  extent rasters are not flood-depth measurements and are not adapted here.
- Rainfall variables are deliberately not converted directly into branch-failure
  probabilities. They must first feed a hydrologic/flood or slope-instability
  model that produces a physically meaningful asset-level hazard measure.

All conversions must be explicit in the fragility configuration. Unsupported
units fail rather than being guessed. Null values remain missing.

## Model

For hazard \`k\` and branch \`i\`, the demonstration uses a logistic fragility curve:

\`p_ik = 1 / (1 + exp(-(h_ik - midpoint_k) / scale_k))\`

Hazard mechanisms are combined using:

\`p_i = 1 - product_k(1 - p_ik)\`

This combination assumes conditional independence between hazard mechanisms.
Branch outages are then sampled as independent Bernoulli variables. Spatially
correlated failures are not implemented in this phase.

**The sample curve parameters in \`weather_fragility_demo.json\` are arbitrary
integration-test values, not engineering thresholds or empirical probabilities.**
Replace them with literature-supported and/or locally calibrated component-class
fragility curves before using the outputs as scientific outage estimates.

## Mapping limitations inherited from Phase 6B

- The 33 bus locations are synthetic samples, not verified Taipower asset sites.
- Branch locations are straight-line endpoint midpoints, not conductor corridors.
- Point observations map to the nearest of 65 sample points.
- Regional observations are broadcast unchanged and excluded from fault generation
  by default; \`--include-regional\` explicitly opts into this coarse proxy.
- Historical reanalysis remains historical; generated scenarios are not forecasts
  unless the input records have \`temporal_semantics=forecast\` or \`scenario\`.

## Run

\`\`\`bash
python scripts/normalize_weather_sources.py --skip-nasa
python scripts/map_weather_features_to_ieee33.py
python scripts/generate_weather_fault_scenarios.py --samples-per-timestamp 100 --seed 42
python -m pytest -p no:dash tests/test_weather_fault_scenarios.py tests/test_weather_feature_mapping.py -v
\`\`\`

Outputs are written to \`reports/environmental/weather_fault_scenarios.json\`.
Each scenario records the failed branch IDs, branch-level probabilities, seed,
temporal semantics, and the resulting connected components and slack-connected
buses.

## Scope and next integration boundary

This phase generates branch-outage scenarios and topology summaries. It does not
yet generate a scenario-specific QUBO, optimize tie closures, model bus/substation
failures, represent spatially correlated failures, or validate voltage, thermal,
protection, or AC power-flow constraints. The existing Bus 6 QUBO remains a
separate fixed-contingency benchmark.
